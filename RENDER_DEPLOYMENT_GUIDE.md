# Deploy Django Backend to Render

This guide will help you deploy your WorkNest Django backend from Railway to Render.

## Prerequisites

1. A Render account (sign up at https://render.com)
2. Your code pushed to a GitHub repository
3. OAuth credentials (Google and GitHub Client IDs and Secrets)

## Deployment Steps

### Option 1: Using render.yaml (Blueprint - Recommended)

1. **Push the configuration files to your repository**
   - The `render.yaml` and `build.sh` files have been created in your project root
   - Commit and push these files to your GitHub repository

2. **Create a New Blueprint on Render**
   - Go to https://dashboard.render.com
   - Click "New" → "Blueprint"
   - Connect your GitHub repository
   - Render will automatically detect the `render.yaml` file
   - Click "Apply" to create both the web service and PostgreSQL database

3. **Configure Environment Variables**
   After the blueprint is created, you'll need to set these environment variables in the Render dashboard:
   
   - `ALLOWED_HOSTS`: Your Render backend URL (e.g., `worknest-backend.onrender.com`)
   - `CORS_ALLOWED_ORIGINS`: Your frontend URLs (comma-separated, e.g., `https://worknests.vercel.app,https://yourdomain.com`)
   - `GOOGLE_CLIENT_ID`: Your Google OAuth client ID
   - `GOOGLE_CLIENT_SECRET`: Your Google OAuth client secret
   - `GITHUB_CLIENT_ID`: Your GitHub OAuth client ID
   - `GITHUB_CLIENT_SECRET`: Your GitHub OAuth client secret
   
   Note: `DJANGO_SECRET_KEY` and `DATABASE_URL` are automatically generated by Render.

### Option 2: Manual Setup

If you prefer to set up manually:

1. **Create a PostgreSQL Database**
   - Go to Render Dashboard → "New" → "PostgreSQL"
   - Name: `worknest-db`
   - Database: `worknest`
   - User: `worknest`
   - Click "Create Database"
   - Copy the "Internal Database URL" for later use

2. **Create a Web Service**
   - Go to Render Dashboard → "New" → "Web Service"
   - Connect your GitHub repository
   - Configure the service:
     - **Name**: `worknest-backend`
     - **Root Directory**: `backend`
     - **Runtime**: Python 3
     - **Build Command**: `pip install -r requirements.txt && python manage.py collectstatic --no-input && python manage.py migrate`
     - **Start Command**: `gunicorn worknest.wsgi:application`

3. **Set Environment Variables** (in the web service settings)
   - `DATABASE_URL`: Paste the Internal Database URL from step 1
   - `DJANGO_SECRET_KEY`: Generate a secure key (use https://djecrety.ir/)
   - `DEBUG`: `False`
   - `ALLOWED_HOSTS`: Your Render service URL (e.g., `worknest-backend.onrender.com`)
   - `CORS_ALLOWED_ORIGINS`: Your frontend URLs (comma-separated)
   - `GOOGLE_CLIENT_ID`: Your Google OAuth client ID
   - `GOOGLE_CLIENT_SECRET`: Your Google OAuth client secret
   - `GITHUB_CLIENT_ID`: Your GitHub OAuth client ID
   - `GITHUB_CLIENT_SECRET`: Your GitHub OAuth client secret

4. **Deploy**
   - Click "Create Web Service"
   - Render will automatically build and deploy your application

## Post-Deployment Steps

### 1. Update CSRF and CORS Settings

Once your backend is deployed, you'll need to update your Django settings with the Render URL:

In `backend/worknest/settings.py`, the following settings should include your Render URL:
- `CSRF_TRUSTED_ORIGINS`
- `CORS_ALLOWED_ORIGINS`
- `ALLOWED_HOSTS`

You can set these via environment variables in Render.

### 2. Update Frontend API URL

Update your frontend environment variables to point to the new Render backend URL:
- In Vercel: Update `NEXT_PUBLIC_API_URL` to your Render backend URL (e.g., `https://worknest-backend.onrender.com`)

### 3. Update OAuth Redirect URIs

Update your OAuth application settings:

**Google Cloud Console:**
- Add `https://your-render-backend.onrender.com/api/auth/google/callback/` to Authorized redirect URIs

**GitHub OAuth App:**
- Add `https://your-render-backend.onrender.com/api/auth/github/callback/` to Authorization callback URL

### 4. Create Superuser (Optional)

To create an admin user:
1. Go to your Render service dashboard
2. Click "Shell" tab
3. Run: `python manage.py createsuperuser`
4. Follow the prompts

Or use the Render CLI:
```bash
render shell worknest-backend
python manage.py createsuperuser
```

## Important Notes

### Free Tier Limitations
- Render's free tier spins down after 15 minutes of inactivity
- First request after spin-down will take 30-60 seconds (cold start)
- Database has 90 days of history retention
- 750 hours/month of service runtime (enough for one service)

### Cost
- **Free Tier**: $0/month
  - 750 hours of runtime
  - Shared resources
  - Services spin down after inactivity
  
- **Starter Plan**: $7/month per service
  - Always-on (no spin down)
  - More resources
  - Better for production

### Database Backups
- Free PostgreSQL databases are backed up for 90 days
- For production, consider upgrading to a paid plan with longer retention

## Troubleshooting

### Build Fails
- Check that `requirements.txt` is in the `backend` directory
- Verify Python version compatibility
- Check build logs in Render dashboard

### Database Connection Errors
- Ensure `DATABASE_URL` environment variable is set correctly
- Verify database is running and accessible
- Check that `psycopg2-binary` is in requirements.txt

### Static Files Not Loading
- Ensure `collectstatic` runs in build command
- Verify WhiteNoise is installed and configured
- Check `STATIC_ROOT` and `STATIC_URL` settings

### CORS Errors
- Add your frontend URL to `CORS_ALLOWED_ORIGINS` environment variable
- Ensure the URL includes the protocol (https://)
- Check that `django-cors-headers` is installed

### OAuth Not Working
- Verify OAuth redirect URIs are updated in Google/GitHub settings
- Check that client IDs and secrets are set correctly in environment variables
- Ensure callback URLs match exactly (including trailing slash)

## Migration from Railway

### Export Data from Railway (if needed)
If you need to migrate your data:

1. **Export from Railway PostgreSQL**
   ```bash
   # Connect to Railway database
   railway run pg_dump $DATABASE_URL > backup.sql
   ```

2. **Import to Render PostgreSQL**
   - Upload backup.sql to your repository or a temporary location
   - Connect to Render database via Shell
   - Run: `psql $DATABASE_URL < backup.sql`

### Environment Variables
Copy these from Railway to Render:
- `DJANGO_SECRET_KEY` (or generate a new one)
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `GITHUB_CLIENT_ID`
- `GITHUB_CLIENT_SECRET`
